# PIC-SURE R Adapter Rewrite — Repository Design

**Status:** Draft for review
**Date:** 2026-04-20
**Branch:** `query_v3` (off `main`)
**Scope:** R repository layout, public API shape, Python environment management via reticulate, wrapper architecture, testing, CI, docs, and branch-setup commits for the `picsure` R rewrite. The Python adapter is a separate repository (`pic-sure-python-adapter-hpds`) and is out of scope.
**Source material:** `pic-sure-python-adapter-hpds/docs/superpowers/specs/2026-04-15-picsure-rewrite-design.md`, `pic-sure-python-adapter-hpds/docs/rewrite/2026 API Adapter Update Methods.txt`.

## Goals

- Replace the existing R adapter's hand-rolled httr/jsonlite HTTP code with a thin R layer over the new `picsure` Python package, wrapped via reticulate.
- Present an R-idiomatic surface (session as first argument, camelCase names matching the Python spec) that feels familiar to existing R adapter users while tracking the Python package's semantics exactly.
- Keep the R code narrow enough that adding a new Python method is a one-file edit on the R side.
- Produce the same quality of error messages the Python package emits, without leaking Python tracebacks to researchers.
- Ship a migration vignette sufficient to get existing R users off the v1 API.

## Non-goals

- Parity with the v1 R surface. `initializeSession`, `addClause`, `deleteClause`, `bdc.*` are gone.
- Re-implementing any backend logic in R. The R layer is purely a wrapper.
- Async. The Python `picsure` package is synchronous; the R wrapper is synchronous.
- Backwards compat at the package-load level — users will see new exports only. A migration vignette is the only bridge.

## High-level decisions

| Area | Decision |
|---|---|
| Package name | `picsure` (unchanged) |
| R floor | `R >= 4.1` |
| reticulate floor | `reticulate >= 1.41` (required for `py_require()`) |
| Python env | `reticulate::py_require("picsure==<pinned>")` in `.onLoad`; ephemeral uv-backed |
| Python module handle | Package-private `picsure_py` via `reticulate::import(..., delay_load = TRUE)` |
| API style | R function per Python method; session as first argument |
| Enum handling | R wrappers accept case-insensitive strings and translate to Python enums internally |
| Error handling | One public condition class `picsureError`, mapped from Python `PicSureError` |
| Testing | `testthat` with `local_mocked_bindings`; live tier gated by `PICSURE_INTEGRATION=1` |
| Coverage gate | 80% via `covr` |
| CI | GitHub Actions: `check.yml`, `integration.yml`, `pkgdown.yml` |
| OS matrix | `ubuntu-latest`, `macos-latest`; Windows deferred |
| Docs | `pkgdown` + Rmd vignettes, including migration guide |
| Versioning | SemVer starting at `0.1.0`; first release pins Python `picsure==0.1.0` |
| Branch | `query_v3` off `main`; first commit wipes v1 sources |

### Rationale for the tree

- **`R/zzz.R`.** Standard R package convention; its filename sorts last alphabetically so its `.onLoad`/`.onAttach` hooks are defined after every other function in the package. The file will open with a header comment explaining both the convention and the file's purpose so future contributors who haven't seen the idiom are not confused.
- **One R source file per Python service area.** Mirrors the Python repo's `_services/` layout; each wrapper file is short enough to hold in head and edit independently.
- **`utils_coerce.R` at the top of `R/`, not behind a subfolder.** R has no package-internal subdirectories; prefix-by-name is the idiomatic way to signal a helper module.
- **Integration tests in a subdirectory of `tests/testthat/`.** Lets `testthat` auto-discover them when the env var is set, and skip them entirely when it isn't.
- **`docs/superpowers/specs/` preserved as in the Python repo.** This spec lives next to future R plans under the same convention.

## Python environment management

**First call experience:**

```r
library(picsure)            # fast — nothing Python happens yet
bdc <- picsure::connect(    # first real call: reticulate resolves
  platform = "BDC Authorized",  # picsure==<pinned> into an ephemeral
  token    = my_token           # uv-backed venv, then imports it
)
```

**How it works:**

- `R/zzz.R`'s `.onLoad()` calls `reticulate::py_require("picsure==<pinned>")`. Purely declarative; no environment is created yet.
- `.onLoad()` also binds `picsure_py <<- reticulate::import("picsure", delay_load = TRUE)`. The import is deferred until the first attribute access.
- When `connect()` invokes `picsure_py$connect(...)`, reticulate materializes the venv (a few seconds on the first run, cached under `~/.cache/reticulate/uv/...`), then the call proceeds. Subsequent sessions reuse the cached env.

**Version pinning policy.** The R package pins an exact Python `picsure` version per R release (e.g., R `0.1.0` pins Python `0.1.0`). Relaxing to a compatible range (`~=0.1.0`) is a later call once the Python package has more than one patch version in the wild.

**`.onAttach` startup message.** A one-line note that the Python env is provisioned lazily on first call, so users are not surprised by a pause later.

### Why `py_require()` over alternatives

- `reticulate::py_install()` into a named venv inside `.onLoad` forces installation as a side effect of loading the package, which is both slower and more opaque than the declarative `py_require` contract.
- Requiring users to manage Python themselves (`RETICULATE_PYTHON`) shifts setup friction onto researchers who came to R specifically to avoid it.
- `basilisk` is appropriate for Bioconductor packages that ship on BiocManager; the added conda weight is unwarranted here.

## Public R API surface

Exported names (one-to-one with the Python public surface; session-bearing functions take `session` as first arg):

```r
# Connection
connect(platform, token, ...)       # → session (opaque Python object)
platforms()                         # → character vector of platform names

# Search
search(session, keyword, facets = NULL, ...)   # → data.frame
facets(session)                                # → facet_set (opaque Python FacetSet)
addFacet(facet_set, key, value)                # → facet_set (mutates underlying Python object)
removeFacet(facet_set, key, value)             # → facet_set

# Query construction (no session needed)
createClause(path, type, min = NULL, max = NULL, categories = NULL)   # → clause
buildClauseGroup(clauses, root = "AND")                               # → clause_group

# Query execution
runQuery(session, query, type = "count")    # → scalar / data.frame
exportPFB(session, query, path)             # → invisible(path)
exportCSV(session, query, path)             # → invisible(path)
exportTSV(session, query, path)             # → invisible(path)

# Errors (condition class, not function)
picsureError
```

Removed vs. v1: every v1 export. No deprecation shims.

### Enum-valued arguments accept R strings

The Python package uses `ClauseType.FILTER`, `GroupOperator.AND`, `Platform.BDC_AUTHORIZED`. The R wrappers accept **case-insensitive strings** (`"FILTER"`, `"AND"`, `"BDC Authorized"`) and translate to the Python enum inside the wrapper. Rationale: notebook researchers should not need to reach into reticulate enum proxies at the R prompt, and string-valued args make copy-paste from docs trivial. The wrapper validates the string against the Python enum before the call so typos error early with R-native messages.

`picsure::platforms()` exists precisely so users can `print(picsure::platforms())` to discover valid values without hunting docs.

### End-to-end R session

```r
library(picsure)

bdc <- picsure::connect(platform = "BDC Authorized", token = my_token)
# > Connected to BDC Authorized as user <id>. Token expires 2026-05-14.

# Search
results <- picsure::search(bdc, "sex")
fs      <- picsure::facets(bdc)
fs      <- picsure::addFacet(fs, "study_ids", "phs000007")
fhs_sex <- picsure::search(bdc, "sex", facets = fs)

# Build query
sex    <- picsure::createClause("\\phs1\\pht1\\phv1\\sex\\", type = "FILTER", categories = "male")
age    <- picsure::createClause("\\phs1\\pht1\\phv5\\age\\", type = "FILTER", min = 40)
copd   <- picsure::createClause("\\phs1\\pht2\\phv2\\copd\\", type = "FILTER", categories = "Yes")
asthma <- picsure::createClause("\\phs1\\pht2\\phv3\\asth\\", type = "FILTER", categories = "Yes")

```

## Wrapper architecture

Every wrapper is a thin, three-step function. Using `search()` as the canonical example:

```r
#' Search the PIC-SURE dictionary.
#' @export
search <- function(session, keyword, facets = NULL, limit = NULL, offset = NULL) {
  kwargs <- drop_nulls(list(
    keyword = keyword,
    facets  = facets,
    limit   = as_py_int(limit),
    offset  = as_py_int(offset)
  ))
  result <- with_picsure_error(do.call(session$search, kwargs))
  py_to_r(result)   # pandas DataFrame → R data.frame via reticulate default
}
```

Three concerns, in every wrapper:

1. **`drop_nulls()`** — remove `NULL` args before the Python call so Python sees its own defaults rather than `None` for things it expected missing. Without this, reticulate maps `NULL` → `None`, which bypasses Python defaults on optional arguments.
2. **`with_picsure_error()`** — a small `tryCatch` that catches Python exceptions, extracts the Python-crafted message, and re-raises as an R condition of class `c("picsureError", "error", "condition")`.
3. **Type coercion on the return** — `py_to_r()` covers the common case; a few wrappers (e.g., `exportPFB`) return `invisible(path)`.

Wrappers live one-per-file in `R/`. Files stay short (most under ~50 lines), so each is easy to hold in head when adding a new Python method.

### Package-private Python module handle

```r
# R/zzz.R

# zzz.R is an R package convention: filenames prefixed with "zzz" sort last
# alphabetically, so the .onLoad / .onAttach hooks defined here run after every
# other function in the package has been defined. This file is where we
# declare our Python dependency and create the lazy module handle that the
# wrappers in connect.R, search.R, clauses.R, query.R, and export.R all call.

picsure_py <- NULL   # package-private handle to the Python `picsure` module

.onLoad <- function(libname, pkgname) {
  reticulate::py_require("picsure==<pinned version>")

  # Lazy: Python env isn't provisioned until first real attribute access
  picsure_py <<- reticulate::import("picsure", delay_load = TRUE)
}

.onAttach <- function(libname, pkgname) {
  packageStartupMessage(
    "picsure loaded. On first call, reticulate will provision an isolated ",
    "Python environment; this takes a few seconds the first time only."
  )
}
```

Every wrapper in the package references `picsure_py`. Tests swap this binding via `testthat::local_mocked_bindings(picsure_py = fake_picsure_py())`, which is exactly where the mocked-unit tier intercepts.

## Error handling

### Public condition class

```r
# R/errors.R

picsureError <- function(message, py_cause = NULL) {
  structure(
    class = c("picsureError", "error", "condition"),
    list(message = message, py_cause = py_cause)
  )
}

with_picsure_error <- function(expr) {
  tryCatch(
    expr,
    python.builtin.Exception = function(e) {
      # Python PicSureError: use the message Python already crafted for researchers.
      # We read it from the captured R condition (reticulate populates conditionMessage
      # with str(exception)), NOT from reticulate::py_last_error()$message which
      # returns a full Python traceback unsuitable as user-facing output. Verified
      # against a live PicSureAuthError on 2026-04-27; see I1 in
      # 2026-04-21-query-v3-review.md and the integration probe at
      # tests/testthat/integration/test-error-extraction.R.
      stop(picsureError(conditionMessage(e), py_cause = e))
    }
  )
}
```

### What researchers see

A Python `PicSureError` surfaces as an R error of class `picsureError`, with the Python-crafted message preserved verbatim and no Python traceback by default:

```
Error: Your token expired on 2026-03-14. Generate a new one at
  https://picsure.biodatacatalyst.nhlbi.nih.gov/ and pass it to picsure::connect().
```

The underlying Python exception is attached to the condition as `$py_cause` so advanced users and bug reports can still inspect it via `rlang::last_error()` and `reticulate::py_last_error()`.

### One class, strict

`picsureError` is the only condition class in `NAMESPACE`. No subclasses. The error-message quality contract is enforced by `test-errors.R`, which asserts on message **content** mirroring the Python package's `test_errors.py`.

## R ↔ Python type coercion

reticulate handles most cases automatically; the sharp edges live in `R/utils_coerce.R`:

| Concern | Helper |
|---|---|
| R `NULL` should mean "arg omitted", not Python `None` | `drop_nulls(list(...))` before `do.call` |
| R `NA` vs. Python `None` ambiguity | `na_to_none()` — explicit for optional scalar args |
| R integer vs. Python int (R defaults to double) | `as_py_int(x)` for `limit`, `offset`, etc. |
| R `list("a", "b")` vs `c("a", "b")` → Python list | `as_py_list()` normalizes to a Python `list` |
| Named R list → Python dict (vs. positional list) | `as_py_dict()` for `categories = c("Yes", "Maybe")` style |
| pandas DataFrame → R data.frame | `py_to_r()` default is fine; column-type edge cases covered in tests |
| Enum strings → Python enum | `to_py_enum(value, enum_cls)` — validates against `picsure_py$ClauseType` etc. |

A dedicated `test-coerce.R` covers each helper. This is where the bugs in a reticulate wrapper actually live, so the unit tier invests here.

## Testing strategy

### Two tiers, mirroring the Python package

**Unit tier (`tests/testthat/test-*.R`)** — runs on every PR. No Python process, no network. Uses `testthat::local_mocked_bindings()` to replace the package-private `picsure_py` handle with a fake that records calls and returns canned values.

`tests/testthat/helper-mocks.R` builds the fake:

```r
fake_picsure_py <- function() {
  list(
    connect = function(platform, token, ...) structure(
      list(platform = platform, token = token, search = function(...) ...),
      class = "fake_session"
    ),
    createClause     = function(...) list(type = "clause", args = list(...)),
    buildClauseGroup = function(...) list(type = "group", args = list(...)),
    ClauseType       = list(FILTER = "FILTER", SELECT = "SELECT", REQUIRE = "REQUIRE", ANYRECORD = "ANYRECORD"),
    GroupOperator    = list(AND = "AND", OR = "OR")
  )
}
```

Each `test-*.R` uses `local_mocked_bindings(picsure_py = fake_picsure_py())` so wrappers call into the fake instead of the real Python module. Tests verify: the right Python method is called, args are coerced correctly (integers are integers, `NULL` was dropped, enums resolved), and Python-side errors raise `picsureError` with the expected message.

Coverage gate: 80% via `covr`, enforced in CI. Target unit-tier runtime: under 5 seconds.

**Integration tier (`tests/testthat/integration/`)** — gated by `Sys.getenv("PICSURE_INTEGRATION") == "1"`. Skipped at collection time when the env var is unset. When enabled, uses real reticulate + real Python `picsure` + real backend (`PICSURE_TEST_PLATFORM`, default `"Demo"`; `PICSURE_TEST_TOKEN` from env). Runs nightly via `integration.yml`; failures open a GitHub issue automatically.

### What the error-message test does

`test-errors.R` asserts on the Python-crafted message content flowing through the R wrapper intact — a token-expired scenario must include the expiration date and a URL, a bad-path scenario must point at `picsure::search()`, and so on. The Python package owns the message text; the R test guards that the wrapper does not mangle it.

### Integration tests are read-only

No mutation of shared backend state. Safe to run nightly without coordinating with whoever else is exercising the Demo environment, and results are repeatable rather than order-dependent.

### Fixtures

No cassette library. For wrapper tests, canned Python call shapes are authored in `helper-mocks.R`. For the integration tier, real responses come from the live backend; no JSON fixture files in the R repo.

## CI / CD

### `check.yml` — every PR and push to `main`

- Matrix: `{ R: 4.1, 4.3, 4.4 } × { OS: ubuntu-latest, macos-latest }`. Windows is intentionally deferred in this first cut — reticulate on Windows has its own sharp edges, and BDC researchers are overwhelmingly on macOS/Linux. Can be added back when a Windows user files an issue.
- Steps: install R → install system deps (libcurl, libssl) → `r-lib/actions/setup-r-dependencies` → `reticulate::install_python()` → `R CMD check --as-cran` → `testthat::test_package("picsure")` → `covr::package_coverage()` with 80% floor.
- Target runtime: ~3 minutes.

### `integration.yml` — nightly schedule + manual dispatch

- Single job: `ubuntu-latest`, R 4.4, real Python env.
- `PICSURE_INTEGRATION=1`; secrets from GitHub Actions.
- Failure opens a GitHub issue via an action (same pattern as the Python `integration.yml`).

### `pkgdown.yml` — PR and push to `main`

- Builds the pkgdown site on PR (fails if any roxygen reference is unresolved — catches missing `@export`, bad `@seealso`).
- Deploys to GitHub Pages on push to `main`.

### No release workflow in this cut

R packages on CRAN require manual submission anyway, and this package is unlikely to be on CRAN for the first releases (installs from GitHub). A `release.yml` that builds source + binary tarballs on tags is a follow-up once install channels are settled.

### No pre-commit hooks

`lintr` and `styler` checks live in `check.yml`. Keeping them off local commits avoids the familiar pattern of contributors reaching for `--no-verify` when hooks slow them down.

## Branch setup and first-commit sequence

The `query_v3` branch is created off `main`; the first three commits establish the empty canvas before implementation plans start landing:

1. **`chore: clear v1 sources for rewrite`** — delete `R/picsure.R`, `R/bdc.R`, `R/query.R`, `R/dictionary.R`, `NAMESPACE`, `man/`, `tests/`, `pseudo-tests/`, `vignettes/`, `picsure_1.1.1.pdf`, `hpds.Rproj`, `pic-sure-r-adapter-hpds.iml`. Keep `DESCRIPTION`, `LICENSE`, `README.md`, `CODE_OF_CONDUCT.md` as scaffolding.
2. **`chore: rewrite DESCRIPTION for reticulate dependency`** — update `Depends`/`Imports` to `reticulate (>= 1.41)`, `R (>= 4.1)`; drop `httr`, `jsonlite`, `stringr`, `hash`, `purrr`, `urltools`, `tidyverse`; bump version to `0.0.0.9000`; update Title/Description for the rewrite.
3. **`chore: README placeholder for v3 rewrite`** — one-paragraph README noting the rewrite is in progress and pointing at the Python package. Full README lands with the last implementation plan.

Subsequent commits land under implementation plans (one plan per service area), following the stacked-branch workflow already in use on the Python side.

## Out of scope for this spec

## Open questions

Nothing blocking the implementation plan. Items that may come up and deserve a sentence when they do:

- Whether `Session` should support `on.exit()`-style cleanup from R. Nice-to-have, not in the first cut.
- Whether `picsure::platforms()` should return a small data.frame with a description column rather than a plain character vector. One-liner in a later plan.

These get revisited during implementation if they become blockers; otherwise they stay on the list for a follow-up spec.
